# TP-102: Don't lose my data if the save file gets damaged

**Type:** Story · **Owner:** Rafi (BE) · **Points:** 3 · **Reviewer:** Mei

## Story
As a tester with weeks of checklists in TestPal, I want my data protected when the save file is damaged or a save is interrupted, so that one bad moment doesn't wipe out my test history.

## Acceptance criteria (DRAFT: finish in `/refinement TP-102`)
- Given `data/testpal.json` contains invalid JSON, when the server starts, then it does not crash or overwrite the file, and it keeps a copy of the damaged file.
- Given the server is saving, when the save is interrupted part-way, then the previous good data is still there on the next start.
- Given the data file was damaged, when I open the page, then I'm told something went wrong instead of seeing an empty app with no explanation.
- _Open: On a damaged file, do we start empty (with the copy kept) or refuse to start until it's fixed?_
- _Open: Where does the copy go, what is it called, and how many do we keep?_

## Dev notes
