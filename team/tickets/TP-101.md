# TP-101: Clear errors for blank, too-long and duplicate names

**Type:** Story · **Owner:** Rafi (BE) · **Points:** 2 · **Reviewer:** Jonas

## Story
As a tester building my checklists, I want TestPal to stop me with a clear message when a name or title is blank, too long or already taken, so that I don't end up with empty or confusing entries I can't tell apart.

## Acceptance criteria (DRAFT: finish in `/refinement TP-101`)
- Given I create or rename a checklist, when the name is empty or only spaces, then it is not saved and I get an error that says a name is required.
- Given a checklist named "Login" already exists, when I create or rename another checklist to "Login", then it is rejected with an error that names the clash.
- Given I add or edit a test case, when the title is longer than the maximum, then it is rejected with an error that states the limit.
- _Open: What are the limits for checklist names, case titles, steps and notes?_
- _Open: Is "login" a duplicate of "Login", and do leading or trailing spaces count?_
- _Open: Are duplicate test case titles inside one checklist allowed?_

## Dev notes
Validation lives in `testpal/lib/checklists.js`; errors go out through `server.js` as 4xx `{ error }`, which the page already shows.
