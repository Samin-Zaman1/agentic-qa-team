# TP-101: Clear errors for blank, too-long and duplicate names

**Type:** Story · **Owner:** Rafi (BE) · **Points:** 2 · **Reviewer:** Jonas

## Story
As a tester building my checklists, I want TestPal to stop me with a clear message when a name or title is blank, too long or already taken, so that I don't end up with empty or confusing entries I can't tell apart.

## Acceptance criteria
Limits are counted after spaces at the start and end are trimmed, and the trimmed value is what gets saved. Every error tells the user exactly what to fix and the page shows it.

**Checklist names (create and rename)**
- Given I create or rename a checklist, when the name is empty or only spaces, then nothing is saved and the error says a name is required.
- Given I create or rename a checklist, when the name is 99 or 100 characters, then it saves and is still there after a reload.
- Given I create or rename a checklist, when the name is 101 characters or more, then nothing is saved and the error says names can be at most 100 characters.
- Given I create or rename a checklist, when the name has spaces before or after 100 characters (for example " " + 100 characters), then it saves without those spaces and is still that way after a reload.
- Given a checklist named "Login" exists, when I create or rename another checklist to "Login", "login" or " Login ", then nothing is saved and the error names the clash ("Login" already exists).
- Given a checklist named "Login", when I rename it to "Login" or change only its capitals (for example to "LOGIN"), then it saves, because it doesn't clash with itself.

**Test case titles (add and edit)**
- Given I add or edit a test case, when the title is empty or only spaces, then nothing is saved and the error says a title is required.
- Given I add or edit a test case, when the title is 199 or 200 characters, then it saves and is still there after a reload.
- Given I add or edit a test case, when the title is 201 characters or more, then nothing is saved and the error says titles can be at most 200 characters.
- Given I add or edit a test case, when the title has spaces before or after it, then it saves without those spaces.
- Given a checklist has a test case titled "Login works", when I add or edit another case in the same checklist to "Login works", "login works" or " Login works ", then nothing is saved and the error names the clash.
- Given a test case titled "Login works" in one checklist, when I add "Login works" to a different checklist, then it saves (duplicates only count inside one checklist).
- Given a test case, when I edit it and keep its own title (or change only its capitals), then it saves.

**Steps, expected result and note**
- Given I add or edit a test case, when steps are up to 5000 characters, or expected result or note are up to 2000 characters each, then it saves; when any is one character over, nothing is saved and the error names the field and its limit.
- These fields may be empty.

**Same rules everywhere**
- Given I use the API directly (for example with curl) instead of the page, when I send any of the inputs above, then I get the same result and the same error message as on the page.

### Out of scope
- Fixing existing saved data that already breaks these rules (old duplicates or over-long names stay as they are until edited).
- Treating look-alike characters, accents or inner spaces ("Log  in" vs "Log in") as duplicates.
- Duplicate checks across different checklists for test case titles.
- Showing a live character counter while typing.
